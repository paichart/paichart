A gate the objective names no approver for is written `UNASSIGNED — no approver declared`, and its `approver.<gate>` row is OPEN — that row, not a line in *Open questions*, is how it reaches the owner. The POV roster you read in `pov.details` says who EXISTS, never who is ACCOUNTABLE — use it only to confirm each DECLARED approver is a team member, and mark one who is not. - **Label the values you state as reference data.** They describe the round's INTENT so a human can read the run; they are never evidence, and restating one is not a check. **The label is a disclosure, not a licence: it does not admit a state value the previous rule excludes, and a validation step whose expected output is a value restated from this document is exactly the restatement this clause forbids.** Where a value is derived rather than carried by the evidence source you named, say it is derived and name the basis — and never write a criterion that asks for a value its own named source structurally cannot supply.
  - **Name the producer of every crossing value, and define every term the acceptance checks turn on.** *"the produced range"* is two values, not one — write *"the range produced by the FABRIC leg"*. A noun phrase missing its subject gets bound to whoever reads it, and two readings of one sentence produce two different DAGs that a planner picks between silently. The same test covers scope words: if "hop", "boundary" or "interface" decides what passes, define its extent where it is used.
  - **Write the constraints that exist only by convention, or accept that they will be violated.** A leg can honour what is in harvested facts or written here — nothing else. A range reserved by habit, a subnet's zero address avoided by custom: unwritten is nonexistent, and invisible to every reviewer.
  - 🔴 **Out of scope is stated as CLASSES, never by naming other objects the harvest found.** Write *"any resource other than the declared target"*, *"any namespace other than the one declared"* — never a list of the other resources, workloads, files or listeners your harvest saw. A named neighbour is harvested state (it goes stale when the estate changes, and it tells the reader what exists today); the class already excludes it.   - **State every existence assumption an objective rests on — as a BRANCH the leg's own harvest decides, never as today's state** (*"if the leg's harvest finds no policy governing the receiver, apply `<token>.enforcer-absent`; if it finds one, apply `<token>.existing-grant`"*; and on an authorisation leg, *"if the harvest cannot confirm the enforcer sees the admitted attribute, apply `<token>.principal-unseen`"*). The branch names WHICH decision governs it and never answers that decision itself — "modify it" silently chose between replacing and preserving what was already there, and 13 revisions split on it. **Every consumer leg carries its existence branch AND its null branch, and each cites its row id** (`<token>.existing-grant`, `<token>.target-empty` or `<producer>.inputs-empty`): a branch that is simply absent is a decision made by silence, and a missing branch has no row to contradict, so nothing else catches it (*one approved generation dropped every branch*). Unstated, it is resolved at runtime as an ambiguity — costing retries at best, a guessed reconciliation at worst. **Never write which branch is true** (*"no policy exists today"*, *"CREATE is the expected outcome"*) — even when your harvest just showed it: that is harvested state, it goes false the moment anyone applies the change, and a program Architect will carry it into its binding contract as fact.

State completeness as a property of the shape ("every line, in order"); never by naming the specific line some earlier attempt dropped.

The temptation is to treat an unprovable absence as a blocker; it is content.
