# Series-cut ledger

> **What this is.** Every deploy, flag flip or reseed that changes what a pipeline agent reads, or how a stored fact is computed,
> is a **series cut**: a before/after comparison across it is a population difference, not a behaviour change, unless stated.
> Each entry names what moved BY CONSTRUCTION, the structural field to key the split on (never time alone), any exclusion
> window, and the rollback. **Newest first. Entries are kept verbatim — never summarise one.**
>

> as do the cuts embedded in their own health-run sections (network 1.19.0 in the non-literal rate section; TEMPLATE-SENT-TWICE
> in the caching section). CLAUDE.md keeps the rule and an index of the latest cuts.
>
> **Adding an entry:** prepend it below this header, in the same shape (cut timestamp = the process restart or reseed that made
> it live; push / release / seed facts; movers keyed on fields; rollback). Then update the index in CLAUDE.md.
