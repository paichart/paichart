## Discovery Scope

### 1. Prompt Architecture (Database-First Strategy)
Document the dual-layer system:
- **Built-in Prompts**: Hardcoded in `/lib/mcp/server/prompts/prompt-registry.js`
  - `audit_all_tasks` - Server-side POV task aggregation (direct Prisma, 6 optional arguments)
  - `authentication_required` - Dynamic auth gate for unauthenticated users
  - Always available, no database dependency
  - Note: Previous built-in prompts (7 original + 3 Hub) were removed; system now uses database-first strategy
- **Database Prompts**: Primary prompt source (chameleon platform strategy)
  - Stored in `agent_prompt_library` table
  - Filtered by `status: 'ACTIVE'` + `tags: { has: 'mcp' }`
  - Loaded atomically via `$transaction` with `ReadCommitted` isolation
  - Cached in LRU Map (max 500 entries) with on-demand fallback
  - Real-time sync via PostgreSQL NOTIFY/LISTEN events
  - Discoverable via `list_prompts` tool and `/prompt` commands

### 2. Prompt Registry Implementation
Document the current registry architecture:

#### **Built-in Prompts (initializeBuiltInPrompts):**
```javascript
// Only 1 built-in prompt remains (line 285):
this.registerPrompt({
  name: 'audit_all_tasks',
  description: 'Lists all OPEN, IN_PROGRESS, and BLOCKED tasks...',
  arguments: [status, povStatus, includeCompleted, maxPerPOV, showAssignees, showPhaseInfo],
  content: this.createAuditAllTasksPrompt.bind(this) // Direct Prisma access
});
```

#### **Database Prompt Loading (loadDatabasePrompts):**
- Atomic `$transaction` with 10s timeout and `ReadCommitted` isolation
- Connection validation via `SELECT 1 as connection_test`
- LRU eviction when cache exceeds 500 entries
- Event emission for real-time registry synchronization
- Graceful degradation: falls back to built-in prompts if database fails

#### **Prompt Resolution Priority (getPrompt):**
1. Check authentication (return `authentication_required` if unauthenticated)
2. Check `dbPrompts` cache (database-first for authenticated users)
3. Try `loadDatabasePromptOnDemand()` (on-demand fallback)
4. Fall back to `prompts` Map (built-in prompts)

#### **Current Architecture (Database-First):**
- **Built-in Prompts (2)**: `audit_all_tasks` + `authentication_required` (auth gate)
- **Database Prompts (dynamic)**: Primary source, MCP-tagged, atomically loaded
- **Event-Driven Sync**: PostgreSQL NOTIFY/LISTEN for real-time CRUD updates
- **Session Resilience**: Atomic transactions + connection validation prevent race conditions

#### **Historical Note:**
Previously (2025-08-17 to late 2025), the registry contained 10 built-in prompts:
- 7 original pAIchart prompts (list_tasks_guided, select_pov, etc.)
- 3 MCP Hub prompts (register_service_wizard, discover_services_conversation, orchestrate_workflow) — now replaced by database prompts
These were removed as the system migrated to a database-first strategy. Some may exist as database prompts now.

#### **Execution Paradigm (NEW - Nov 15, 2025):**

**Critical Understanding**: Server-side prompts use **different execution context** than MCP tools

**Two Execution Paradigms in MCP Server**:

1. **MCP Tools** (External Interface - for AI clients):
   - Execution: AI client → MCP protocol → Tool handler → `apiClient.get()` → API layer (HTTP) → Database
   - Examples: project(action: 'task.list'), services(action: 'discover')
   - Pattern: Expose `_meta.pagination` for client-side iteration
   - Use case: AI clients paginate through results themselves
   - File: `/lib/mcp/server/tools/sdk-native-*.js`

2. **Server-Side Prompts** (Internal Functions - aggregation/analysis):
   - Execution: Prompt registry → Direct `prisma.findMany()` (same Node.js process, no HTTP)
   - Examples: audit_all_tasks, workflow prompts
   - Pattern: Manual `count()` for server-side completeness detection
   - Use case: Server aggregates data, returns complete summary
   - File: `/lib/mcp/server/prompts/prompt-registry.js`

**Why Different**: Server-side prompts run INSIDE MCP server process (direct DB access, faster), MCP tools provide external interface (must go through API layer for consistency/security)

**When Discovering Prompts**:
- Does it aggregate/analyze data? → Server-side prompt (use direct Prisma)
- Does it provide data for AI client? → MCP tool (use apiClient + _meta.pagination)
